# 任务阶段与执行日志

失败和超时账号默认展开详情，用户手动收起后，轮询更新不会重新强制展开。正常账号的详情使用“当前阶段”，失败账号使用“失败阶段”；没有阶段说明的终态任务不会显示“等待 Worker 处理”。详情展示已保存的尝试次数、开始和结束时间。

每个账号可打开“执行日志”，也可从任务卡片查看全部账号日志。日志按时间排列，支持账号筛选，并保留任务级事件作为上下文。窗口打开时每 2.5 秒增量刷新，也可手动刷新。关闭窗口、切换任务或退出登录后，旧请求不会覆盖新窗口的内容。

`GET /api/v1/tasks/{task_id}/events` 保留 SSE 响应格式，支持：

- `limit`：每页条数，默认 200，范围 1–500。
- `afterEventId`：上一页最后一条事件的 ID；必须属于同一任务且是公开事件。

事件按 `created_at, event_id` 升序排列。客户端读满一页后继续翻页，不再只显示最早 200 条。SSE 的 `event: end` / `data: {}` 是流结束标记，不是日志记录。用户身份、CDK 和任务归属校验仍适用于每一页，控制消息不对外展示。

新进度事件增加 `stageStatus`（阶段结果）和 `attempt`（任务尝试次数），原 `status` 仍表示任务项状态。例如单个阶段的 `fail` 不等于任务已结束。Worker 开始事件随领取事务保存，完成事件附带任务状态、尝试次数及是否等待重试。

历史记录保持兼容；未保存的阶段结果、尝试次数或历史日志不能追溯生成。页面仅显示公开的结构化阶段、说明、状态和错误字段，不展开原始凭证或引擎消息。

验证包括前端构建与 18 项前端测试，以及任务事件、事件分页、引擎事件协议和 Worker 重试的离线回归测试。测试使用模拟响应或临时 SQLite 数据库，未创建真实业务任务。
