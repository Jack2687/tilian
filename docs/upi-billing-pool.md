# UPI 账单池与输入校验

账单地址由 `engines/pay153-checkout-link-main/upi_link_service.py` 处理。当前主池有 78 条静态地址，覆盖 49 个城市、24 个邦/联邦属地；通用解析器的 35 条印度地址全部包含在主池内。

## 选择规则

- 合并静态地址来源后，按街道、城市、邦和邮编去重；统一空白、大小写及已支持的城市别名，不再额外随机追加重复记录。
- 没有填写地址时，从有效池中选择整行地址。街道、城市、邦和邮编始终来自同一条记录。
- 多个候选可用时，同一引擎进程连续两次池选择不重复；只有一个候选时可复用。独立任务使用独立子进程，不保证跨任务、跨进程地址唯一。
- 已填写完整且通过本地校验的地址直接保留，不消耗池选择，不查询代理城市。姓名与邮箱按原有调用方优先规则处理。
- 只传姓名、邮箱、空 `address` 或印度国家提示，仍视为未填写具体地址。显式填写了街道、第二行、城市、邦、邮编中的任何内容，就必须提供完整可校验的地址。
- 地址在一次建单尝试中解析一次，税费、账单快照和确认请求复用相同结果。

## 本地校验范围

国家接受 `IN` / `India`，未传时兼容默认 `IN`。邦必须是已知两字母代码或邦名全称；输出统一使用邦名全称。邮编必须是六位 ASCII 数字且首位非零。

城市、邦与邮编前三位须匹配池中的已知组合。例如 `Mumbai / MH / 400026` 可通过，`Mumbai / KA / 110001` 会被拒绝。支持 Bangalore/Bengaluru、Bombay/Mumbai、Gurgaon/Gurugram 等常用别名。

这不是完整的邮政地址认证：不验证门牌与投递能力，也不覆盖印度全部城市和邮区。未覆盖或输入不一致时返回清晰错误，不静默替换用户地址。

账单 JSON 格式错误、非对象、部分地址或校验失败统一返回 `reason_code=upi_billing_invalid`、`retryable=false`。Worker 同样把该原因码列为终态，修正输入后再提交。

## 同城选择与缓存

`UPI_BILLING_SYNC_CITY` 默认关闭；关闭时完全跳过代理城市探测。启用后，也只在未填写地址时探测。结果在进程内按代理缓存，当前调用使用局部城市变量，避免不同调用混用城市。

同城池没有候选时仍使用全池。印度地址来源不读取/写入通用 JSON 地址缓存，不调用地图查询接口；代理城市查询是独立的可选操作。

## 验证

本轮离线验证 85 项通过：67 项 UPI 账单、CLI、金额、SetupIntent 及相关现有用例，18 项后端适配和重试用例。测试使用虚构输入和 mock，没有创建真实提链任务。
